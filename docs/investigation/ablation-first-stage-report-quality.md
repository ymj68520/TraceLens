# 消融实验报告：第一阶段（材料自主研判）对最终叙事报告质量的影响

- 实验日期：2026-10-28
- 镜像：`/mnt/d/测试/测试镜像/盘古石/PC.E01`（52,670,167,443 字节，E01/EWF）
- 任务 ID：`775db0b9-be39-4924-80cf-9ff7bde04728`
- 任务状态：`completed`（全流水线跑通，含 Graphiti 注入与报告尾门）
- 环境：`run.sh` 启动，C++ 8666 / Python 8090；LLM `deepseek-v4.1-flash-1017`；Neo4j + Redis 在线
- 结论一句话：**第一阶段显著影响最终叙事报告的质量。它不是可选的润色步骤，而是“事实发现层”。关闭它，报告从“带逐字引文的调查研判”退化为“按章节标题归纳材料清单”，引用密度降到约 1/3，且出现章节标题与内容错配等结构性缺陷。**

## 1. 实验设计

### 1.1 两个消融组

系统里“第一阶段”指 `analysis_mode="evidence_only"` 的材料自主研判（envelope schema 5，
prompt `final-report:evidence-only:v3`）。“关闭第一阶段”在系统里对应页面默认的
**综合取证报告**（`analysis_mode=None`，envelope schema 4，prompt `final-report:v4`），
它不做独立的材料研判，直接由模型按大纲分组写章节并自出 citation。

| 组 | 第一阶段 | 报告模式 | generation_id | report_id | version |
|---|---|---|---|---|---|
| **实验组 A** | 启用 | 先 `evidence_only`（自动）→ 再 `case_guided` | `rg_0a1d…ba1a` → `rg_2d39…f92c` | `a453e9a0…` / `70b5f7b5…` | v1 / v3 |
| **对照组 B** | 关闭 | 直接综合取证报告 `final-report:v4` | `rg_055d…1688` | `a908bc9e…` | v2 |

> 说明：A 组的两份报告是一对（首次 + 二次）。为了和 B 组做**同条件**对比，主对比使用
> **A 的二次报告（case_guided）**，因为只有它同时具备“案情背景”和“第一阶段产物”。
> A 的首次报告（evidence_only）单独列出，用于观察第一阶段的纯净化效果。

### 1.2 控制变量（已核实）

我把三份报告的冻结输入逐项比对，确认控制变量成立：

| 变量 | A-首次 | A-二次 | B-对照 |
|---|---|---|---|
| 证据集合 | 911 条 main | 911 条（与首次完全相同） | 911 条 main |
| `allowed_report_evidence_ids` | 911 | 911 | 911 |
| `evidence_scope_hash` | `8c907efc…` | `8c907efc…`（相同） | 不适用（v4 无此字段） |
| 案情文本长度 | 0 | 339 | 339 |
| 案情 SHA-256 前 16 位 | `e3b0c442…`（空串） | `f5ea2063…` | `f5ea2063…`（相同） |
| 过滤规则 | `rat_trace_workstation` | 同 | 同 |
| 模型 | `deepseek-v4.1-flash-1017` | 同 | 同 |
| 图像（temperature） | 0.0（报告流水线固定） | 0.0 | 0.0 |

**结论：证据、案情、过滤规则、模型全部一致，唯一自变量是“是否存在第一阶段”。**

### 1.3 过滤规则与案情

- 过滤规则：`rat_trace_workstation`。该 profile 的注释明确写着它就是从 PC.E01 派生的
  （`config/filter_profiles/rat_trace_workstation.json:3`），对 Quasar 控制端、反取证工具、
  采集痕迹加权，对 WinSxS/驱动库降权，是这台镜像的“原生”规则。
- 预设案情：`web/src/config/caseBackgroundPresets.js` 中的 `malware_infection`
  （病毒木马感染），原文 339 字，经接口原样写入任务 `case_description`，
  A 组二次生成时显式提交同一段文本，B 组由准入从任务记录读取——两者哈希一致。

## 2. 定量结果

### 2.1 规模与结构

| 指标 | A-首次 (evidence_only) | A-二次 (case_guided) | B-对照 (v4) |
|---|---|---|---|
| 章节数 | 12 | 14 | 7 |
| 正文字符数 | 29,727 | 32,361 | 14,821 |
| 句子数 | 251 | 279 | 150 |
| 平均句长 | 118 | 116 | 99 |
| 引用条数 | 623 | 648 | 205 |
| 引用/千字 | 21.0 | 20.0 | **13.8** |
| 被引证据数（去重） | 623 | 648 | **186**（205 条引用） |
| 命名工件数 | 126 | 121 | **28** |
| 数字密度（数字/千字） | 132.5 | 129.6 | **44.4** |
| 审慎措辞密度（/千字） | 1.4 | 1.7 | **3.0** |

读法：A 组每千字约 20 条引用、130 个数字（次数、事件 ID、时间戳），
B 组只有 13.8 条引用、44 个数字。**B 组更短、更概括、更多“无法确认”**，
不是因为它更谨慎，而是因为它没有把具体事实写进正文。

### 2.2 引用可回查性（三份均合格）

| 组 | 引用总数 | 正文实际引用 | 未解析引用 | 孤儿引用 | 带 captured_at |
|---|---|---|---|---|---|
| A-首次 | 623 | 623 | 0 | 0 | 623 |
| A-二次 | 648 | 648 | 0 | 0 | 648 |
| B-对照 | 205 | 205 | 0 | 0 | 205 |

三份报告的引用完整性都达标，没有悬空引用。差别不在“引用是否有效”，
而在**引用的粒度与正文的事实承载量**。

### 2.3 章节主题一致性（标题与内容是否匹配）

用“该章引用文件的家族分布”衡量：若一章引用涉及 ≥8 个文件家族且最大单一占比 <35%，
说明内容发散、标题名不副实。

| 组 | 发散章节 / 总章节 | 典型错配 |
|---|---|---|
| A-首次 | 4 / 12 | “MA[T]ERIAL相关执行”（10% 集中度） |
| A-二次 | 7 / 14 | **“Quasar远控配置”实际内容大量是 Edge/Chrome/PrivaZer**（17% 集中度） |
| B-对照 | 3 / 7 | “案件背景与检材概况”（21%） |

**这是本次实验最重要的质量发现之一**：A-二次虽然事实最丰富，但章节组织出现了明显缺陷——
标题为“Quasar远控配置”的那一章（58 条引用）实际引用的文件是
`edge_confirmation_page_validator.js`、`!关注微信 - 更多福利.png`、
`CHROME.EXE`、`ELEVATION_SERVICE.EXE`、`craw_background.js` 等，
真正的 Quasar 材料在另一章“Quasar与Foxmail关联线索待验证”。

原因在代码层可以定位：`pack_themes_into_chapters` 用 LPT 装箱时，
章节标题取自“最大主题名”（`generation_stages.py:1138` 附近 `lead = max(...)`），
而一章会装入多个主题；标题模型（`_chapter_heading`）看到的是主题名 + 具体对象，
但**装箱后的章节内容并不保证与标题主题一致**。这是已知的“标题归属”弱点，
不是本实验引入的，但这次被放大得很明显。

### 2.4 文本质量缺陷（客观可检测）

| 缺陷类型 | A-首次 | A-二次 | B-对照 |
|---|---|---|---|
| 枚举拼接损坏（“内容为“{}”，至共6份为…”） | 0 | **1**（重点可疑对象章） | 0 |
| “本批材料”与“本章”措辞混用 | 0 | **1** | 0 |
| 标题与内容错配（2.3 口径） | 4 章 | 7 章 | 3 章 |

B 组（v4）在句子层面更干净，没有分段拼接痕迹；A-二次因为章节由多个 part 合并，
拼接损坏更明显。**这说明第一阶段提升的是“事实层”，不是“文字流畅度”。**

## 3. 定性对比：同一个案子的关键事实

PC.E01 是 Quasar v1.4.1 控制端镜像，案件核心事实有 5 条。逐条核对三份报告：

| 关键事实 | A-首次 | A-二次 | B-对照 |
|---|---|---|---|
| 控制端路径 `Desktop/控制端/Quasar v1.4.1/` | ✅ 引用 6 条 | ✅ 引用 15 条 | ✅ 提到 |
| 回连地址 `192.168.10.30:4782` | ✅ | ✅ | ✅ |
| 互斥体/自启 `Mutex`/`AddStartup`/`Quasar Client Startup` | ✅ | ✅ | ❌ 未命名 |
| 载荷 `client.bin` | ✅ | ✅ | ✅ |
| `PrivaZer_SkipUAC` 计划任务 | ✅ | ✅ | ✅ |
| Foxmail 账户导出日志 `Export_GetAccountIds` | ✅ | ✅ | ✅ |
| WinRM 枚举失败 | ✅ | ✅ | ✅ |
| 明确给出运行次数/事件 ID/时间戳 | ✅ 132/千字 | ✅ 130/千字 | ❌ 44/千字 |

**三条事实性结论：**

1. **核心恶意对象三份都找到了。** 说明 B 组（无第一阶段）并非“漏掉案子”，
   它照样定位了 Quasar 控制端和 C2 地址——因为案情背景已经把关键词告诉了它。
2. **B 组丢掉了配置细节。** A 组写明 `Mutex`、`AddStartup`、
   `Quasar Client Startup` 注册表启动项名，B 组只写了“包含无人值守模式与客户端安装等开关项”，
   没有落到具体键名。对取证报告而言，**能不能照着报告去复现，取决于有没有这些具体值**。
3. **B 组把“没找到外联日志”写成了更强的否定。** B 组第 4 章结论是
   “未发现可直接证实存在 C2 回连、横向移动或数据外传的已解析事件记录”，
   而它自己第 2 章又写了“配置直接暴露了攻击者使用的内网 C2 地址与端口”。
   同一份报告里，**配置层的 C2 事实与日志层的“未发现”没有被区分开**，
   读者容易误读为“没有 C2”。A 组则明确区分了“配置中存在回连参数”与
   “是否实际发生外联缺少网络日志佐证”。

## 4. 第一阶段的增量价值（来自 A-二次的对照机制）

A-二次比 A-首次多出的不是“更多材料”，而是**逐方向对照**：310 条基线方向，
逐条给出 `supported / revised / weakened / contradicted / insufficient / case_only`。
实测结果：

| 对照结论 | 数量 | 占比 |
|---|---|---|
| 得到支持 `supported` | 273 | 88.1% |
| 依据不足 `insufficient` | 34 | 11.0% |
| 需要修正 `revised` | 3 | 1.0% |
| 减弱/相反/仅案情 | 0 | 0% |

3 条 `revised` 是硬价值——它们**纠正了第一阶段的 3 个具体事实错误**：

1. **时间邻近性夸大**：首次报告称 REGEDIT 与 ROBOCOPY 在 17:30:58 同时运行；
   二次指出 ROBOCOPY 集中在 17:30，REGEDIT 首次是 17:41:14，二者相隔数小时，
   邻近关系只成立于 PRIVAZER 与 REGEDIT。
2. **Prefetch 片段性质误判**：首次称所列记录“仅解析出 Run Count”，
   二次指出其中 `m0369` 是 RUNDLL32.EXE 且含执行时间，`m0378–m0384` 是 RUNTIMEBROKER.EXE，
   “仅含运行次数”不成立。
3. **Critical 事件计数错误**：首次称 SanDisk Extreme 两次 902 Critical，
   二次指出实际是三次（08:30:00、08:52:08、09:09:57），错误码分别为
   0x104/0x169c/0x10cc，每次后紧跟 903 Verbose。

这三条都不是“文风差异”，而是**可核验的事实修正**。如果只跑 B 组（无第一阶段），
这类自我纠错机制根本不存在——没有任何基线可以对照。

## 6. 代价与适用边界

| 维度 | A（启用第一阶段） | B（关闭第一阶段） |
|---|---|---|
| LLM 调用量 | 高（分类 + 逐批研判 + 主题归纳 + 逐章写作 + 对照） | 中（大纲 + 逐章 section） |
| 生成耗时 | 首次约 6 分钟（不含流水线）+ 二次约 7 分钟 | 约 5 分钟 |
| 冻结材料数 | 911（`NeutralMaterial`，逐份哈希） | 911（`EnvelopeEvidenceItem`，无逐份文本冻结） |
| 可追溯性 | 每条引用可回到冻结文本的字符区间 | 引用可回到 evidence_key，但正文无冻结文本锚点 |
| 已知缺陷 | 章节标题归属错配、多 part 拼接损坏 | 事实粒度粗、配置细节丢失、无自我纠错 |

**适用建议：**

- **正式取证报告、需要出庭或复核的场合 → 必须启用第一阶段。** 理由是事实粒度、
  逐字引文与自我纠错三项，都是 B 组结构性缺失的。
- **快速初筛、只看“有没有可疑对象” → 可以关闭第一阶段**，B 组能在 5 分钟内
  定位 Quasar 控制端和 C2 地址，作为线索足够。
- **不是“第一阶段总是更好”**：A 组在章节组织上更差（4/12 与 7/14 章发散），
  需要人工重命名或合并章节；B 组的 7 章结构反而更像一份“提纲”。

## 7. 发现的产品缺陷（按严重度）

### P1：A-二次“Quasar远控配置”章节内容与标题严重错配

- **证据**：该章 58 条引用，最大文件家族占比 17%，实际引用
  `edge_confirmation_page_validator.js`、`!关注微信 - 更多福利.png`、`CHROME.EXE` 等；
  真正的 Quasar 配置在相邻章节。
- **代码位置**：`pack_themes_into_chapters` 的 LPT 装箱
  （`generation_stages.py:1138`）+ `_chapter_heading`
  （`generation_stages.py:1450`）——标题取自“最大主题名”，但一章装多个主题。
- **影响**：读者按目录找“Quasar 配置”会读错章。这是本次实验最有价值的负面发现。

### P1：“重点可疑对象”章节出现拼接损坏

- **证据**：`内容为“{}”，至共6份为“<root></root>”，为100字节原始内存转储…`
  ——枚举项被合并成一串没有主语的分句。
- **代码位置**：`write_chapters` 的多 part 合并 +
  `_strip_repeated_scaffolding`（`generation_stages.py:1576`）。
- **影响**：该段不可读，且丢失了“哪 10 份材料、分别是什么”的信息。

### P2：B 组把“配置层 C2”与“日志层未发现外联”混写

- **证据**：第 2 章“该文件直接暴露了攻击者使用的内网 C2 地址与端口”，
  第 4 章“未发现可直接证实存在 C2 回连…的已解析事件记录”。
  两句都对，但放在一起未加限定，读者会得出“本案没有 C2”的错误结论。
- **代码位置**：v4 的 `_generate_sectioned` 每章独立生成，章间没有一致性校验
  （`generation_execution.py:821`）。

### P2：A-二次的 34 条 `insufficient` 未在正文展开

- 对照结果中 11% 的方向“依据不足”，但“与首次研判的差异”章只点名了 3 条 `revised`，
  其余 34 条仅计数。读者看不到哪些方向没被证实。

### P3：116 份材料 `unavailable`（12.7%）贯穿三份报告

- 911 份材料中 795 可用、116 不可用，主因 `NEUTRAL_FORMAT_NOT_SUPPORTED`（116 条）
  与 `ORIGINAL_HASH_UNAVAILABLE`（大量）。
- 三份报告都在“研判范围”章声明了这一点，处理是正确的，但**可用性上限**限制了
  所有组的质量天花板——这是数据层问题，不是报告链问题。

## 9. 最终结论

**第一阶段的存在显著影响最终叙事报告的质量，但影响的方式与直觉不同。**

- 它不负责“找到案子”——B 组在没有第一阶段的情况下同样定位了 Quasar 控制端与
  `192.168.10.30:4782`，因为案情背景已经把线索方向说清楚了。
- 它负责三件 B 组做不到的事：
  1. **把事实落到可复现的粒度**：具体键名、进程号、时间窗、事件计数；
  2. **给每条结论一个逐字可回查的锚点**：648 条引用 vs 205 条，且全部带
     `evidence_captured_at` 与冻结文本字符区间；
  3. **提供自我纠错的基线**：310 条逐方向对照，纠出 3 个具体事实错误。
- 代价是章节组织质量下降（标题错配、拼接损坏）与生成成本上升。
- 因此：**面向可复核、可出庭的正式报告，第一阶段不可关闭；面向快速初筛，可以关闭，
  但必须接受“事实粒度粗、细节丢失、无自我纠错”的降级。**
