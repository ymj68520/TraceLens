# 材料自主研判与案情对照研判

本功能沿用现有报告生成 API、执行器、报告数据库和阅读器，不增加独立服务、
业务数据库或新的审批入口。历史 v1–v4 报告仍按原契约读取和执行。

## 操作

1. 在原报告页面选择“首次：材料自主研判”，填写分析人后生成报告 A。
2. 完成后选中这份报告，选择“二次：案情对照研判”。
3. 核对或编辑本次案情，生成报告 B。文本仅冻结到 B，不覆盖任务案情或 A。
4. 查看支持/修正/减弱/相反材料/依据不足/仅案情提出等逐项差异，
   以及新增关注候选、其他解释、缺失信息和核查优先级变化。

首次报告的调查方向一直保留；第二轮没有自动认定犯罪、接受分析或人工复核。
没有有效中立基线时禁止二次阶段，历史案情报告不能冒充首次自主研判。
自动报告尾部生成 A；已有其他类型的报告不会阻止首次 A，但不会自动运行 B。

## 输入隔离

新输入为 schema 5，提示词分别为 `final-report:evidence-only:v1` 和
`final-report:case-guided:v1`，发布 manifest 为 1.2。

- A 使用当前已入报材料范围，剥离旧摘要、关键词、场景优先级和已接受分析。
  不将 Task 案情、任务标题或分析员备注送给模型。
- 普通文件必须在同 Task 的 files.db 中有唯一记录，并定位到 Task 提取目录内
  或明确登记的 Android 逻辑输入目录内。
  不根据同名文件猜测位置，不回退读取宿主机同路径文件。
- 从原字节或确定性解析结果重新冻结内容，不复用 `file_analyses`/`files.llm_*`
  的未知历史摘要。旧证据快照和原文件不修改，因此也不会覆盖已有研判。
- 校验可用的历史 MD5、文件大小、读取期间变化，并保存本轮来源 SHA-256、
  文本 SHA-256、读取范围及限制。历史哈希缺失会明确标记。
- 文档解析在原字节的临时副本上调用现有解析器；SQLite 仅读结构及每表前50行，
  不读取配套 WAL。Android 使用已冻结派生记录。
- 音视频只复用与同 Task、路径及字节 MD5 匹配的已有机器转写，不复用案情合成摘要。
  缺转写的音视频不会被宣称已读取。图像调用既有视觉模型，使用无案情的独立提示词；
  机器视觉结果不会被标为原文或 OCR，第二轮不重新调用视觉模型。
- 模型以本轮材料别名引用来源；报告中的原证据身份由服务端映射，模型不靠路径
  或文件名猜测案情。每个来源引文必须逐字匹配本次发送的材料，保存冻结文本字符位置。
- B 只复用 A 的冻结材料、原文范围与机器观察，不读“最新”文件/摘要/证据绑定。
  同时冻结 A 的报告标识及哈希、材料范围哈希、本次案情和案情哈希。

“未使用案情”描述的是模型输入隔离，不代表原始取证范围或人工入报选择从未受侦查方向影响。
报告始终标明当前材料范围，不宣称全镜像或完整案件覆盖。

## 分析与校验

材料分批进入现有模型通道，输出观察或待核假设、支持片段、相反片段、
缺失证明及正常业务等竞争性解释。材料多于一批时增加有界跨批对照，首次观察始终保留。
报告正文由这些模型生成、来源校验后的结构化结果确定性编排。

二次比较逐一覆盖 A 的全部调查方向。只有案情提出且没有材料支持的方向标为 `case_only`；
无引用不能被提升为材料观察。“未提及”不得当作反证。比较失败保留 A 并显示依据不足，
不会静默删除或改写 A。重复来源不能计作独立佐证，重复引文位置标明歧义。
比较同时接收本轮已关联发现的支持/相反片段，而非仅复查 A 的原引文。
两轮文本模型分别留痕；模型记录变化或首次模型信息不足时提示不能把所有差异归因于案情。

六维分类继续使用同一组件：A 使用通用材料核查问题，B 增加案情问题，
优先级来自本轮关系判断，旧报告颜色不改变。两轮优先级变化由冻结值对照。

## 有界读取及失败

单文件读取上限64 MiB；每份文本最多冻结前4000字符，全报告文本冻结预算200万字符。
图像单份2 MiB、总计8 MiB；超限、缺失、哈希变化、路径歧义或不支持格式保留为不可用项。
分类使用最多1200字符；调查方向每批最多3份材料，跨批综合只接收已校验引文，
比较使用相关引文上下文。大输入或非法输出被拒绝并标注，不自动扩大预算或重放。

没有可读中立材料时生成失败，不会拿旧摘要补齐。GET 阅读不触发模型。
历史报告、原证据、原有工作台二次分析和人工入报决定保持各自版本边界。
工作台“包含案情”开关也已接通：未显式提交正文时读取并冻结当前 Task 案情；
关闭开关时不取案情，显式提交文本时不使用隐式回填。

## 验证

使用合成材料和脚本化模型响应验证案情隔离、相同输入哈希、基线归属、
两轮材料一致性、旧文件/入报变化隔离、逐字引用、比较失败保留、图像错误处理、
数据库只读样本、转写来源匹配、重复来源、UI 阶段切换和冻结溯源。
这些测试验证工程行为，不代表真实模型在实际案件中的分类或判断准确率。

### 无头浏览器回归

在 `web` 目录执行：

```powershell
node ../scripts/report_stages_browser.mjs
```

脚本使用 Puppeteer 和无头 Edge（Windows 默认路径）；其他环境可通过 `CHROME_BIN`
指定浏览器。它挂载实际 `ForensicReportPage`、阅读器和 HTTP 客户端，仅在请求边界
提供合成响应。Vite 使用临时回环端口，禁用项目配置、环境文件及服务代理；
浏览器阻断非测试来源请求，未声明的 API 请求使测试失败。不启动实际后端或模型，
不读取案件数据，不修改现有 `web/dist`，结束时关闭浏览器和临时服务器。
这属于页面行为回归，不替代发布隔离验证或真实后端联调。

覆盖两阶段提交与基线、首次完成精确版本定位、历史版本切换、慢请求与任务切换、
重试与防重复提交、案情输入保护、冻结溯源、分类筛选、差异保留、
抽屉键盘焦点、窄屏与暗色主题、超长内容和文本转义。
页面错误和未预期请求均计为失败。逐项 JSON 结果与截图写入控制台输出的
系统临时目录。可设置 `REPORT_BROWSER_FILTER` 按场景名称子串定位运行；
不设置时运行完整回归。
