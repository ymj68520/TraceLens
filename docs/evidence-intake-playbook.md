# 未知检材现场适配：赛前预检与分流

本流程处理**已经取得的文件或镜像**。实体手机采集取决于授权、设备状态、工具与人员资质，不能通过文件导入接口代替。预检、哈希完成、解析完成、证据核验是四个不同状态。

## 赛前准备

将待检查的目录、镜像或容器放在服务器证据目录（默认项目上级目录，环境变量 `TRACELENS_EVIDENCE_INBOX` 可更改）。Task 页展开“检材预检”，选择候选检材：

- “快速识别”只看文件头、有限目录清单和小型 ZIP 的中央目录，不计算完整来源哈希，不解压或执行内容。
- “后台计算完整 SHA-256”对单文件流式哈希；目录逐文件哈希并生成 JSONL 清单，目录清单摘要**不是**原介质哈希。
- 未知 MFC/M01/mf/bcp 仅按扩展名标为低置信度的厂商容器候选；不宣称已解析。大 ZIP/7z 只识别容器，内部清单需隔离环境再检查。
- 快速目录清单上限 20,000 文件或 15 秒，完整哈希清单上限 1,000,000 文件；触顶显示 `partial`，不能作为完整检材清单。大量小文件的挂载盘可能在快速模式中提前触发时间上限。

只有完整哈希或目录逐文件清单哈希已计算、格式已识别为现有 Android 目录/逻辑 ZIP/MIUI 备份且预检无部分结果时，界面才提供“按此来源新建 Android Task”；这只是预填路径与来源类型，不是把哈希校验结果绑定为解析成功的证明。目录清单不是不可变快照，后续仍应核查源文件未变化。原始镜像候选还需验证分区与文件系统，未知容器和第三方报告不能由该按钮伪装成安卓原始检材。

输出记录状态、格式猜测与置信度、文件数、读取字节、完整性状态、哈希/清单、归档路径逃逸与加密告警。目录内的嵌套镜像/容器仅按后缀列为候选，并不递归打开或宣称已识别。后台任务中断不会被当成“已校验”。任何后续解析必须仍保留来源文件和源路径，不能以厂商 HTML 报告冒充原始提取数据。

## 现场判断

1. 核对采集授权、软件版本、采集方法、设备/镜像状态、密码或密钥来源；保持原件只读。
2. 完成来源登记与哈希。多分卷、嵌套容器和加密状态另行记录，不能仅凭扩展名确定类型。
3. 若为现有支持的 E01/DD、Android 逻辑目录/ZIP、MIUI 备份，先抽样核对原始文件、数据库表/行或字节位置及解析覆盖，再运行全部分析。
4. 若为未知专有案例容器，寻求授权的原厂导出接口或开放格式导出；无法导出时明确标记“不支持”，不猜结构、不运行随包可执行文件。
5. 若只有 HTML 报告，仅使用“第三方派生报告”只读索引；报告的表格行数不等于原始手机记录数。

安卓解析数据库中的 `android_source_coverage` 记录候选来源的 `parsed`、`staged_for_parser`、`no_candidate_path`、`extract_failed` 和 `locked_or_unsupported`。前端显示解析条数和失败/缺失项；“未找到”不能证明数据不存在，“已提取”也不能证明所有行已解析。
逻辑安卓 Task 即使走完流水线，若来源覆盖缺失或仍有待核对项，完成消息与任务元数据会标明 `android_coverage_status=incomplete`；任务进度 100% 只表示本轮处理结束，不代表取证完整。

验收时至少核对每类关键数据的源路径、哈希及若干原始记录；未完成的格式、加密库、缺失附件和时间区解释应写入覆盖报告。现场没有样本前，不承诺未知专有格式的适配工期。
