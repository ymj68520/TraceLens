# 案件管理与可选 AI 服务解耦

案件名称、描述、Task 关联、列表/详情和删除案件记录由 C++ `/api/cases` 维护。
旧网页经 `/api/llm/cases` 代理，导致关闭出站模型时基础 CRUD 被误拒绝为 503。
前端改用同源、带当前用户 JWT 的既有 C++ 接口，不扩大匿名例外或关闭认证。

从已有 Task 组案只写案件关联，不创建新 Task，不重复取证，不写旧分析库或 v7。
新增关联校验 Task 是否完成、是否已有输出路径，区分已关联、未找到、未完成和权限错误。
返回 `analysis_state_prepared=false`，不能将“已关联”冒充为 AI 复用状态已准备。
新图片任务遵循当前模型策略，不再为了新建案件无条件启用 LLM。

删除案件仅删除案件元数据记录；已有 Task/分析产物保留。删除关联 Task 仍需明确单独确认。
跨镜像 AI 请求和报告生成仍使用原可选分析接口，本次不启用它们。
接口错误不再同时显示“暂无案件”，支持重新加载。

回归采用隔离数据目录/端口/网络命名空间，真实服务和标准 JWT，
验证合成案件创建、详情、关联幂等、角色拒绝和删除，生产只读验证旧案件列表和详情。
不删除或改写真实案件、Task 和历史调查库。
