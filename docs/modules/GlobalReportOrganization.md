# 全局报告组织

第五步在原报告生成任务内增加全局规划。入口仍为材料自主研判、案情对照、原报告阅读与导出，不增加用户操作流程。输入 v8 对应发布 manifest 1.3 和 `final-report:*:v3`；旧 v1–v7 继续按冻结的历史契约执行，旧输入与报告不改写。

## 执行与来源约束

`generation_execution.py` 在原 generation_id 内依次执行：冻结来源 → 逐窗口发现提取 → 来源核验和精确去重 → 全局提纲 → 分章草稿 → 全文校验和辅助复核 → 原事务发布。中间结果保存在既有 `reports.db` 的 `report_planning_artifacts`，以输入哈希绑定并禁止更新、删除。失败不发布半份正文，不回退成材料清单。

发现分为材料观察、模型推断和待核假设。引文必须逐字出现在实际发送窗口以及冻结文本中，保存来源哈希、冻结文本哈希和字符位置。位置采用 Unicode 字符索引，不是原镜像偏移。模型位置错误而引文唯一匹配时，服务器确定准确位置并记录修正；重复引文必须明确位置。实体只在相关材料其他位置出现时，单独保存出现片段，不能用共同出现证明动作关系，原观察降为推断并附限制。无效候选逐条隔离，受影响来源保留部分状态与拒绝原因。

精确去重保留原始发现和来源映射，不把相似描述当成同一事件，也不把同内容来源当作独立佐证。矛盾集保留有反向片段的发现，标记未决；当前没有对所有跨来源语义矛盾做穷尽识别。只有带可靠时区的记录时间进入确定性时间排序，其他时间保留原文和依据，不推造时间线。

## 正文与附录

提纲确定 4 或 6 个主体章节：范围、环境与主体、活动、关联解释、未决事项、结论。材料少时合并为 4 章。正文数量、字符和上下文额度在写作前分配。正文代表发现优先保留反向材料，并在主题及来源类别间分散选取；重复 Prefetch 等单类记录不再仅凭稳定标识占满概述、结论。活动章在选择后按可验证时间排序。

每段绑定发现与允许引用；反向片段必须随相关解释呈现。服务器从段落映射生成 `used_claim_ids`，不依赖模型冗余汇总数组的顺序，但仍要求交代全部已规划发现。正文禁止批次话语、内部标识及清单拼接。来源校验、known_hosts 与离线配置语义检查、确定性时间检查和辅助模型复核共同执行；合法引用并不等于语义解释已被证明。

单章过长先在临时结果中压缩或重写，通过后才合并。明确发现来源解释问题后，重写及再次复核仍失败会阻止发布；初次辅助复核没有完成则可产出标有未复核限制的初步报告。发布时重新从正文与映射校验发现、支持/反向片段、位置、引用及哈希，防止仅有合法摘要而遗漏来源关系。

完整覆盖清单、正文未展开原因与来源审计单独保留，正文不把其余章节堆到最后一章。前端增加中文质量与预算说明、折叠附录及准确引文位置。新报告使用显式引用标记，不按文件名猜引用位置。原 HTML/Markdown 导出入口保留正文和附录，来源文本按字面值转义。

## 冻结预算

| 配置 | 默认值与含义 |
| --- | --- |
| `REPORT_BODY_TARGET_CHARS` | 12,000，正文目标，标点计入；少量材料可更短 |
| `REPORT_BODY_MAX_CHARS` | 20,000，正文硬上限 |
| 单章占比 | 不超过实际正文总字符的 35% |
| `REPORT_APPENDIX_MAX_CHARS` | 200,000，覆盖附录正文预算 |
| `REPORT_MAX_FINDINGS` | 2,000，发现提取上限 |
| `REPORT_BODY_FINDINGS` | 72，正文候选上限，最终受章内上下文限制 |
| `REPORT_GLOBAL_MAX_CALLS` | 512，单次生成派发上限，包含重试和复核 |
| `REPORT_GLOBAL_MAX_TOKENS` | 0 时按调用数乘冻结上下文计算；非零显式限制 |
| `REPORT_GLOBAL_MAX_SECONDS` | 1,800，单次生成时间上限 |

预算使用 `report_planning_budget` 和 `report_planning_calls` 原子预留。同 generation_id 的重试不重置额度。令牌按完整请求 UTF-8 byte-BPE 保守上界计量，不是实际计费值；输出按实际派发上限预留，截断响应拒绝并入正文。图像没有可靠令牌上界时明确暂缓，不把元数据当作图像正文。正文、覆盖附录的字符预算不包含审计 JSON 和导出中的冻结来源明细；后者必须保留完整性，文件大小会更大。
