# 文件来源身份与统一读取

本适配保留原有索引、筛选、提取、分析、调查工作台和报告流程。普通文件新增来源标识；移动设备派生记录仍使用原 Android artifact 契约。

## 来源索引

`raw.db` 完成采集后建立 `source_index_meta` 和 `source_objects`，并向 `files.source_id` 回填标识。筛选与分类复制同一索引版本，不根据派生数据库的新行号重新编号。

物理文件定位包含原始索引行号、分区、inode、删除状态、逻辑路径、大小和时间；逻辑备份保存条目号、容器和应用位置，不把条目号表示为手机物理 inode。当前物理读取对象为默认数据流，不宣称支持 NTFS ADS。

`source_id` 是规范定位描述的 SHA-256，身份范围是一次采集索引。它不是原始镜像完整性认证。源路径、文件大小和修改时间用于变更探测；提取组件另有 SHA-256、MD5 与大小。完整镜像哈希沿用原有采集记录。

同一路径的多分区、现存和删除记录分别保留。路径请求必须唯一；有歧义时返回候选来源，禁止选择第一条。inode 兼容接口仅对已证明同分区、同 inode、同大小与时间的现存硬链接允许同对象读取。

## 原流程中的读取契约

原接口 `POST /api/forensics/files/materialize` 接受 `task_id`、`path` 与可选 `source_id`。数据库和检材路径只从任务解析。

提取结构为 `extracted_files/by-source/<source_id>/payload/<原名>`；清单位于其父目录的 `source.json`，避免证据原名为 `source.json` 时被覆盖。已发布副本校验后复用，不在并发读取时重写。

内部分析引用为 `source:v1:<source_id>:<原路径>`；新文件证据键为 `file:v2:<source_id>:<百分号编码路径>`。界面显示原始路径，分析保存、版本查询、音视频转写缓存、时间线、报告候选与引用跳转保留来源身份。

Python 的 `source_reading` 校验任务归属、定位描述、清单、大小和哈希，再提供保留原文件名的临时副本。交互分析、批量分析、重分析、Office/MarkItDown 预览和报告冻结均使用该契约。宿主机上恰好存在的同名绝对路径不构成来源证明；旧库明确登记的绝对路径还必须位于任务或注册提取目录内。

## SQLite 与解析状态

按签名识别 SQLite，因而无扩展名的 History 仍可解析。WAL/journal 配对依据同一次采集、分区、路径和删除状态；鸿蒙还核对应用容器。歧义、错配或读取失败不改用另一份记录。

在隔离副本中打开 SQLite，验证 WAL 头、页大小、salt、帧校验和与提交边界。原始副本不 checkpoint、不生成 SHM。路径与上下文关联不等于密码学证明 WAL 必然属于某次数据库会话，验收记录保留这一边界。

默认主文件读取上限 256 MiB，组件包 320 MiB。SQLite 最多读取 64 张表、每表 50 行，具有时间与文本预算；覆盖情况与正文分开保存，抽样不表述为全量。

无解析器、格式损坏、来源不唯一或校验失败均保留不可用状态。诊断不能进入证据正文。文本解析不把临时目录、提取清单或报错当作文件内容。

## 历史兼容

新报告使用 V6 输入封装及 `source_policy=source-locator-and-read:v1`。V1—V5 继续读取；新增可选字段为空时不写入旧序列化形态。旧报告、冻结输入和证据键不批量回写，不自动补造来源身份。历史路径已出现歧义时，需要显式选择来源。

## 验证

单元测试覆盖跨任务隔离、同路径多来源、哈希篡改、元数据重名、WAL 损坏、分析单行保存、时间线独立身份、历史序列化与 HTTP 歧义返回。`tests/integration/test_source_read_contract.py` 使用合成镜像检验原生索引、原名、WAL 和镜像哈希保持不变；`source_materialize_probe` 仅为离线集成测试驱动。

真实 PC.E01 验收材料和测试输出保存在任务外部的 `output/source-identity-fix-20261025`，不提交真实检材或 API 密钥。
