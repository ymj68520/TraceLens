# 校验与中文交付

第六步继续使用任务、摄取作业、报告生成、版本阅读及导出接口。执行状态与质量结果独立：`completed` 只表示执行结束，不表示全部材料已分析或结论已经核实。

## 报告质量与发布

`report_quality.py` 从指定版本的冻结报告生成只读质量视图，不修改旧 manifest 或输入哈希。新报告区分“来源与结构校验通过”“有范围限制”；运行中为“待校验”，失败为“校验或执行未通过”，没有质量账本的旧报告为“历史版本未评估”。关键结论始终需人工核对。

叙事版本读接口、生成轮询接口和调查工作台报告视图返回质量及原因。所有暂缓、不可用和部分读取来源都有计数，原因可展开；不把未处理项显示为无关。生成轮询也执行 manifest 结构、任务/生成/输入身份检查，不能把损坏的正文通过轮询接口作为完成产物返回。

新发布快照在原原子目录内同时保存 `manifest.json` 与 `manifest.sha256`。读取时核验独立字节摘要；历史快照没有该侧记时按原冻结契约读取，不在读取过程中补写历史文件。来源文本与片段仍按第五步契约核验。当前新报告的发现、限制、其他解释和正文须有中文说明，原始英文证据、名称、时间、标准术语与机器字段不翻译成伪造原文。

## 来源、摄取与任务状态

候选计划接口从完整候选集合汇总可读、有效零记录、仅元数据、未支持、解析失败和未探测数，再裁剪审计预览；不按 50 条预览估算全量。只有成功解析且明确记录数为零的来源计入有效零记录。执行账本另提供模型失败与尚未处理数，计划 ID 明确绑定当前版本。

图谱摄取保留原 worker 状态，单独计算本次运行质量。908/909 成功会显示 1 条失败并提供“重试未完成摄取”，复用原已分析数据摄取接口及既有幂等机制，不创建另一条分析流程；该动作重新检查既有已分析范围，并非新的逐失败行专用 API。未知计数显示“未记录”，不伪装成零失败；全部失败、计数不一致和未知状态分别保留质量限制。

作业列表按创建时间和运行编号稳定倒序，先按任务过滤再取限额，当前面板不累加历史运行。任务指定的作业查询对跨任务 ID 返回同样的未找到结果。前端普通导入改为轮询实际作业，删除固定十秒后虚报完成的定时器；重新摄取也展示本次成功/失败计数。

原生任务 API 与持久化序列化的完成时间在运行、待运行、暂停或中断时为空；真实终态才显示实际结束时间。重启中断时刻使用独立字段，不当作完成时间。原恢复与报告等待门控保持原流程，续跑验收核对了账本复用和来源不变。

## 离线导出

现有 `html`、`markdown`、`print` 接口共用 `offline_delivery.py`。同一报告路径增加 `offline` 下载包；原工具栏接通离线 HTML、离线包和版本历史，使用明确 task_id/report_id，不回退到其他版本。

包内包含 `report.html`、`report.md`、`sources.json`、`claims.json`、`manifest.json`。HTML 自带样式、无脚本和外部依赖，可通过 `file://` 在断网环境打开；段落引用编号跳转到来源附录。附录包含主张、段落映射、覆盖、哈希、原文及 Unicode 字符位置。旧报告只有章节引用时明确按章展示，不猜逐句位置；旧版未冻结原文或摘要时明确标注缺失。

导出投影仅复制当前报告冻结文字和允许的来源字段，不复制完整检材、图像字节、运行提示或本机提取目录。它不是经过个人信息脱敏的副本，`redaction_applied=false`；证据原文本身仍可能含敏感信息。导出投影有独立 `export_id`、`projection_sha256` 和导出模式。原报告摘要以规范 JSON UTF-8 为基准，`manifest_hash_basis` 明示该口径；包索引保存每个内容文件的字节数和 SHA-256。

离线 ZIP 使用固定成员时间生成确定性内容，以包哈希命名，保存在该任务/报告版本下；既有内容不一致时拒绝覆盖。正文、文件名和引文均按字面转义，CSP 禁用脚本、网络资源及表单。打印保留可查编号与完整附录。浏览器不会从包中请求后台 API、CDN 或登录。
