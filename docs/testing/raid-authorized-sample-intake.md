## 对开发顺序的影响

当前只有完整、干净的Linux MD v1.2已通过合成重组验收，不能据此宣称这22组
实验模型已经兼容。应优先补齐无MD元数据的RAW成员适配与布局候选生成，
复用已保存的开源条带读取器，保留候选歧义，不通过目录名或文件编号猜盘序。

正式验证需要单独完成：

1. 每组显式选择成员，随机打乱输入顺序；尽可能使用匿名输入标识。
2. 自动识别参数，输出盘序、条带、布局、数据偏移及可核对的依据。
3. 在隔离工作目录重组并检查文件系统、目录记录、实际文件读取及内容哈希。
4. 读取前后核对原始样本哈希；不将结果写回样本目录。
5. 如果提供独立已重组参考镜像，比较逻辑字节或明确约定的文件内容；参考
   镜像只用于验收，不能作为候选推断输入。
6. 区分自动推断、显式参数重组、仅结构可读与内容对照通过。不能用“文件系统
   能打开”替代准确重组，不能把失败/歧义样本静默从覆盖分母删除。
7. 在现有Task、查询、提取、研判和报告来源链完成后再执行最终业务回归。

目录中的说明提及另有独立重组参考镜像，但获准目录中暂未找到；已向用户
询问其位置。没有参考时，可做结构/一致性验证，但内容对照缺口必须保留。
教学样本通过，也不等于项目方真实RAID检材或TB级规模已通过。

symlink拒绝、文件数/深度/时间上限、全量哈希及改变检测。没有归档解压、
下载或自动执行入口；新代码沿用AGPL-3.0-or-later。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/raid_sample_manifest.py \
  --samples '/mnt/d/取证/RAID' \
  --output-directory /root/tracelens-raid-validation --full-hash
PYTHONDONTWRITEBYTECODE=1 python_service/.venv/bin/python -m pytest \
  tests/raid_validation/test_sample_manifest.py -q --import-mode=importlib -p no:cacheprovider
```
