# 案情报告证据分类

本功能接入现有 `ReportGenerationExecutor` 和叙事报告阅读器，不增加服务、
任务入口、数据库表或审批业务。原“生成报告”操作和流水线自动报告均使用新契约。

## 数据与生成

- 新输入：`schema_version=4`、`final-report:v4`、
  `classification_policy=evidence-dimensions:v1`。历史 v1/v2/v3 仍按原契约执行。
- 核验冻结输入后，现有模型通道按最多 6 份材料一批分类；只处理本次入报集合，
  不读取最新分析来替换冻结输入。每份材料最多发送 1200 字符的摘要或派生记录，
  截断明确记录。案情片段只作为待核事项。
- 类型、业务主题、问题关系、核查优先级、材料状态、分类复核状态分开保存。
  主题允许多选，第一个主题负责章节归属。未知主题归入“待分类材料”，
  不因路径、删除状态或未命中旧规则而认定为系统噪声。
- 普通文件依据来自初次分析摘要，明确显示“尚未核对原文”；
  Android 依据来自冻结的派生解析记录，不宣称原始数据库行已核验。
- 模型只能返回限定枚举、同批材料身份、已给出的待核事项及逐字依据摘录。
  非法 JSON、重复或遗漏材料、跨来源摘录、未知问题和模型伪造复核字段均被拒绝。
  依据摘录的核验容忍空白差异（换行/缩进等复制痕迹），跨来源文本仍无法通过。
  协议校验失败的批次会把具体校验错误附回模型自动重试一次；重试仍失败的
  材料保留为“未评估”，不删除、不冒充低优先级。
- 分类和正文、引用一起原子发布在现有 manifest 中，新的 manifest 版本为 `1.1`。
  现有 narrative GET 返回冻结的 `evidence_classifications`，没有新增分类接口。

## 阅读

| 标记 | 颜色 | 计算口径 |
| --- | --- | --- |
| P1 优先核查 | 深橙 | 有待核事项的不一致线索，或支持关键问题的机器建议 |
| P2 重点关注 | 蓝 | 有明确支持线索 |
| P3 一般参考 | 灰 | 仅为背景关系 |
| 未评估／依据不足 | 中性虚线 | 关系无法判断、分类失败或没有可用内容 |

颜色只表示核查顺序。正文引用、分类概览和侧栏使用同一冻结结果。
材料清单可按优先级、主题和材料状态筛选；不会删改报告正文。
统计按材料身份计数，同一材料多次引用不重复计数。
没有分类信息的历史报告显示“历史未分类”，不在打开时调用模型。

新机器结果的复核状态固定为“分类待复核”。显示组件识别机器建议、待复核、
分类已确认和人工已调整四种标记，但本次不新增分类确认或编辑业务；
现有“正文/附录”“接受分析”不会被转换成分类已确认。
已删除不等于已恢复，没有恢复事实时不生成“已恢复”标记。

## 验证范围

Python 测试覆盖分类边界、批次失败保留、问题关联、优先级、多标签、Android
派生记录、新报告发布/读取和旧版本兼容。前端测试覆盖颜色文字、维度分离、
去重计数、筛选和引用侧栏。浏览器布局使用合成数据验证桌面、移动端及暗色主题。
合成模型响应仅用于验证协议和流程，不代表真实模型分类准确率。
