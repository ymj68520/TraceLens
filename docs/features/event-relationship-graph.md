# 事件关系图与智能关联

## 入口和行为

现有知识图谱页面保留综合图、人员图和优先级关系网，增加：

- **事件—证据图**：读取已有调查事件及准确的证据关联，保留孤立事件；两个事件引用同一个 evidence_key 时显示“共同关联材料”，不合并事件。
- **证据关联图**：展示调查事件、捕获的证据、所选分析版本及结论；保留尚未关联事件或分析的已捕获材料。分析版本选择沿用调查工作台规则（已接受优先，必要时展示待复核）。
- **智能事件关联**：查看显式分析生成的人员—事件和事件—事件建议。
- **通讯关系图**：跳转现有通讯取证关系分析。当前任务入口保留 task_id，微信和 QQ 导入入口分别选择自己的账号来源，不自动跨平台合并人物。

查看、筛选、切换图谱和来源回查只读，不运行模型、不初始化调查库、不摄入 Graphiti、不生成报告。
人员、事件、证据分别使用图形区分。人物颜色沿用所选人员版本的核查等级；不把人物的等级传播给事件。

## 显式智能分析

1. 展开“发起人员—事件与事件关联分析”，填写分析人。
2. 选择已有调查事件（最多50个；留空时按准确ID顺序取本轮前50个），以及可选的已完成人员版本。
3. 可填写案情语境和本轮目标对预算。案情及事件叙述只是语境，不能作为来源引文。
4. 点击生成新版本。运行、完成、失败、取消及历史版本都保留；查看历史时不会被晚返回的新任务切换。

未选择人员版本时仅评估事件之间的关系。选择人员版本不会重新发现人物或重新解析文件。
所有参与线索、事件关联和差异都显示为机器建议、待核查，不是案件事实或犯罪身份认定。
同文件出现仅形成“关联材料中被提及”；参与线索必须额外经过模型分析和引用校验。

## 准确绑定与回查

调查输入在同一个只读 SQLite 事务中捕获，包括事件ID、叙述版本、证据快照及原有分析/结论引用。
输入与结果使用规范化哈希保存；完整快照哈希与展示文本哈希分开记录。
人员绑定保存准确 people_run_id、结果哈希、人员ID及提及ID，不能按姓名合并。
同名人物和同名事件继续保持独立。

参与分析要求人员材料与调查证据快照的文件字节版本匹配：

- 新人员发现版本保存字节MD5，与调查快照MD5比对，并保留原SHA256。
- 老人员版本缺少MD5时，可只读检查原提取副本，同时验证人员版本SHA256及调查快照MD5；不重新解析、不调用模型。
- 老版本核对最多20份文件、累计64 MiB；缺失、发生变化、超限或没有可比哈希时标为版本未核对。
- 未核对的提及保留提示，不进入“参与线索”模型输入。模型也不能凭姓名借用其他人物的来源。

模型每次只接收服务端确定的一对目标。端点由程序保存，模型不能创建新的端点或证据。
引文必须逐字属于本次实际提供的片段，事件关联必须覆盖双方的来源；人员参与引文还必须包含该人员提及的原始称呼。
初次分析摘要、Android工件、原文字段、解析文本、机器转写等来源分别标明，摘要不能冒充已核验原文。

当前数据的来源详情必须携带画布读取时的 source_version；数据改变时返回409要求刷新。
历史详情始终读取冻结内容，当前事件、人员版本或来源发生变化/无法核对时单独提示，不覆盖历史。
证据详情显示准确快照、引用片段和截断情况，事件可跳回调查工作台定位。

## 时间和关系语义

本期不构造时间先后或因果边。文件创建/修改时间、事件簇时间与行为发生时间不同，保留原快照字段供核查。
没有识别到人物、没有建议或没有连线，都不能解释为没有活动或没有关联。
共同证据边来自准确 evidence_key 的交集，只表示引用同一材料；没有证据的孤立事件仍显示。

## 覆盖与预算

- 查询最多捕获500个事件、2000份证据快照、6000个上下文节点。
- 共同材料边最多5000条，整体关系最多25000条；原始数量、捕获数量和截断状态均返回。
- 每份来源最多6000个文本字符，总计1000000字符；完整快照展示每份最多128000字符、累计4000000字符。超限保留完整内容哈希及截断标识。
- 人员版本最多读取500人、每人前20条提及，关联片段最多2000份、累计1000000字符，提及边最多5000条。
- 智能分析最多选择50个事件。目标对先按共同材料，再按准确ID稳定排序；默认最多100对，上限500对。
- 每对目标每端最多4个来源，每段最多1600字符；事件叙述仅作有界语境。单调用180秒，全任务30分钟。
- 展示后端先筛选、后应用画布上限；画布最多1000节点。清单独立分页，每页最多100条。
- 显示未选事件、未纳入目标对、依据不足、失败调用、无效建议、来源受限及未核对版本数量。
- 每次查询返回筛选条件、来源版本、规则版本、去重规则；智能结果另保留模型、提示词、人员结果哈希和冻结案情。

## 存储、生命周期与兼容

复用当前 Python 服务、模型客户端、PeopleGraphService 的准入锁、串行模型槽、任务注册及关闭管理。
事件任务和人员任务共享 owner_epoch 和每任务唯一运行限制，互不误判为服务重启。
复用 investigation.db 中的 graph_analysis_runs，operation为event_association。
人员列表与事件列表在SQL查询限制之前按操作类型分开；两个API不能读取对方的run。
原调查库版本、事件叙述、证据快照、审核记录、报告及Graphiti数据不因本功能分析而改写。
取消（包括执行前取消）及关闭有持久终态；重启记录显示中断，可重新提交。

接口均在原 `/api/graphiti` 下：

- `GET /event-views`、`GET /event-views/detail`：当前已登记数据及准确来源。
- `POST /event-analysis/runs`：显式提交。
- `GET /event-analysis/runs`、`GET /event-analysis/runs/{run_id}`：列表及状态。
- `GET /event-analysis/runs/{run_id}/graph`、`GET /event-analysis/runs/{run_id}/detail`：冻结视图及来源。
- `POST /event-analysis/runs/{run_id}/cancel`：取消。

所有入口由现有字段权限机制保护，客户端不能传入数据库路径、模型结果或冻结快照。

## 验证

后端：`python -m pytest tests/unit/test_event_graph.py tests/unit/test_people_graph.py -q`。
前端（web目录）：`npm test -- --run src/components/knowledge-graph/EventGraphPanel.test.jsx src/components/knowledge-graph/PeopleGraphPanel.test.jsx`。
无头浏览器：`node scripts/event_graph_browser.mjs`。

浏览器使用实际KnowledgeGraph页面、画布和HTTP客户端，以合成响应替代后端，禁用环境文件、代理和外部网络请求；系统临时目录保存截图和结果。
这些测试检查契约、版本边界和交互，不代表真实案件的模型准确率或人物身份核验结果。
