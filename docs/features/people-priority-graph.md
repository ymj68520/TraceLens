# 人员关系图与案情优先级

## 入口和流程

现有“知识图谱”页面新增“人员关系图”和“优先级关系网”页签。
两个视图共用选定分析版本；查看中心只改变查询范围，不改变核心标记或评分。
原综合图谱、实体/关系浏览、摄入、入报和两阶段报告流程不变。
新增任务在当前 Python 服务进程内执行，复用当前文本/视觉模型客户端，
不调用 `kg_sync`，不触发报告尾部回调，不新增部署服务或业务数据库。

1. 填写分析人，核对本轮案情及读取/评估上限。
2. “发现／更新人员与关系”读取当前任务登记文件，识别人物提及和有来源的关系，
   再根据案情进行评估。案情留空时只保留发现，等级为未评估。
3. “按当前案情评估／继续未评估”复用选定版本的冻结材料及身份分组。
   案情、规则或优先级提示词变化时清空旧评分重新评估；
   同口径继续评估时先处理尚未尝试的目标，避免来源不足的目标阻塞后续目标。
4. 每次发现、评估、身份调整均生成新版本。失败/取消不覆盖已有版本。

GET 仅查询已保存结果和来源状态，不调用模型、创建数据库、升级调查库或重建图谱。
原图不可用时人员发现仍可进行；显示原图优先级未覆盖，不能等同原图没有关系。

## 人员和身份

人物提及从冻结文字逐字定位，保存来源、引文、Unicode 字符位置、来源与文本哈希。
名称必须出现在引文中，关系两端必须引用同批有效人物且两端名称出现在关系引文里。
账号、组织及常见系统账号不纳入自然人。无关系人物照常保留。
案情只进入评估步骤，不作为文件人员发现的输入。

相同姓名默认保留为不同人员候选，并显示同名待区分。
自动归组仅限来源明确记载、校验位有效的18位居民身份证号码，
且同一号码对应名称无冲突；该归组仍为机器识别，不证明实际身份已核验。
电话号码、员工号等不作自动身份合并依据。
同一号码对应冲突名称时保留各候选并标记“身份标识冲突”。
别名或相同身份推测可作为 `identity_candidate` 关系显示，不自动合并。

人工归组需要选择至少两个候选、填写分析人及理由；多个不同身份号码不能直接合并。
人工拆分选择一个人物的部分提及，剩余提及至少一条。
两种操作都严格保持所有提及的唯一归属，新建版本并清空人物/人员关系的旧等级，
原图关系评分保留。原版本及操作人、理由、来源提及始终可追溯。
重新发现时仅沿用所有来源提及仍匹配的人工分组，不能套用的数量单独显示。
身份操作沿用既有 `review` 权限，不修改原始证据或已有审核结论。

## 优先级和图形语义

关系及人物分别评估；一个P1关系不会自动把所有邻居或整张网提升。
AI针对冻结案情问题输出 supports/inconsistent/background/unknown、关键问题标记、
理由和来源引文；程序校验目标、问题与引文后确定等级：

| 等级 | 规则 | 显示 |
| --- | --- | --- |
| P1 | 有材料依据的不一致，或支持关键待核问题 | 深橙 |
| P2 | 有支持线索但未达到关键问题条件 | 蓝 |
| P3 | 仅背景关联 | 灰 |
| 未评估 | 未尝试、依据不足、失败或未知关联 | 中性空心节点 |

核心人物是 P1 人物的附加机器建议标记，使用紫色、大节点及双外圈；
可为零个或多个，不按频次或中心性强制选择一个。
同名身份未区分或身份标识冲突的候选不自动显示为核心。
选择节点的白圈、设为查看中心都不改变等级。
P1可能是重要知情人或被害人，颜色不表示犯罪身份。

共同出现、身份对应建议与直接/待核关系分别保存；
默认人员图只展示直接和待核关系，不把同一文件里的所有人物两两连接。
可按人物等级、核心、待核问题、业务关系名称、关系性质、姓名、文件、
身份待区分、无直接关系人物筛选。
“显示一层上下文”加入的邻居和关系以淡色/虚线显示，原等级不变。
人员列表分页独立于画布上限。原图优先级视图先筛关系再保留端点，
端点不继承关系等级。

## 原图关系与来源

新增严格查询 `get_priority_snapshot`，按任务 `group_id` 和关系 UUID 排序，
在任何画布节点上限之前读取关系；已失效关系不作为当前关系评估。
冻结关系表述、端点、来源 Episode，并显式记录总数、捕获数和来源截断。
案情 Episode 标记为 `case_description`，不能作为关系评分的材料依据；
只有关系表述、没有可引用来源的关系保留为未评估。
初次分析摘要仍可作为优先核查的线索，但展示来源类型，不称为已核验原文。
模型输出的引文必须来自对应目标实际提供的来源，不能跨目标借用其他片段。

来源抽屉读取本轮冻结内容，显示提及、引文、身份归组和相关关系；
原文件链接明确表示打开当前提取副本，可能与冻结版本不同。
引文位置不是磁盘偏移或原PDF页码。没有精确文件来源时不按同名文件回退。

## 覆盖与预算

登记文件目录不按已有 AI 分析、案情相关性或入报状态过滤。
默认读取200个文件，最多500个，按路径稳定排序；未纳入的数量展示。
只读取同任务唯一登记路径及受控提取副本（沿用现有中立来源路径/哈希校验）。
来源不唯一、哈希/大小变化、缺失或超限时不猜测替代。

- 单文件字节上限64 MiB；单文件最多100000个解析字符，总文本1000000字符。
- 识别块3200字符、重叠200字符，最多300块；达到提及/关系预算后后续块不处理。
- 文档使用既有解析器的临时副本，解析覆盖尚未核验时标为部分。
- SQLite沿用既有每表前50行样本解析，未读取WAL；不宣称全库人员覆盖。
- 音视频复用与任务、路径及字节MD5匹配的已有转写。
- 图片最多5份、每份2 MiB；只要求读取可见文字，不识别人脸身份，结果标为机器读取待核。
- 原图关系默认500条，最多2000条；Episode最多2000个、每个最多4000字符，
  总文本1000000字符。读不到、预算排除和文本截断均记录。
- 每轮优先级默认100个目标，最多1000个；不足时保留未评估，允许继续。
- 目标最多读取8个来源片段，每段最多1600字符，截断信息保留在评分中。
- 单次模型调用180秒，整个任务30分钟；取消/关闭有持久终态，不留“永久运行”记录。
- 画布最多1000节点，清单每页最多100项；版本列表读取最近100个版本。

“完整处理”只表示本轮文字及分块处理完毕，不保证模型穷尽识别所有人物。
页面展示完整、部分、不可读、未纳入、身份待区分和失败块数量。
没有识别到人物不等于材料中没有人物，不能把未知/失败降为P3。

## 存储与兼容

由 `InvestigationRepository.prepare_graph_analysis_storage` 在显式分析提交时安装
`graph_analysis_runs` 辅助表、索引和不可变触发器。
原调查库v8、证据快照、审核和报告表的契约及 `user_version` 不变。
旧v7库遵守已有受控升级要求，读操作不升级。
运行输入、结果分别存规范化哈希；终态记录不可原地改写。
人物提及、身份分组、关系、标注及调整历史保存在同一版本化结果中。

保存 task、actor、case快照、基线结果哈希、来源哈希、原图快照哈希、
实际成功模型记录、发现/评估提示词与规则版本。
文件或任务案情改变、原图快照变化会标记历史结果；原图无法核对时标记未知，
不静默认定仍为当前。来源状态检查最多复用10秒缓存，并保留检查时间。
历史内容继续可回查。人工身份写入另做实时材料状态核对。

## 接口与测试

位于现有 `/api/graphiti/people-analysis/runs` 下：

- `POST /`：discover或assess，显式发起；
- `GET /`、`GET /{run_id}`：列表、状态；
- `GET /{run_id}/graph`：后端筛选、画布和分页清单；
- `GET /{run_id}/targets/{target_id}`：准确版本的来源回查；
- `POST /{run_id}/identity/review`：人工合并/拆分，新建版本；
- `POST /{run_id}/cancel`：取消本轮。

所有请求绑定真实任务和准确run ID，客户端不能提交数据库路径、冻结输入或模型结果。
模型只提出建议；不自动入报、审核通过、修改已有实体或重新摄入。

后端：`python -m pytest tests/unit/test_people_graph.py -q`。
前端（web目录）：`npm test -- --run src/components/knowledge-graph/PeopleGraphPanel.test.jsx`。
无头浏览器（web目录）：`node ../scripts/people_graph_browser.mjs`。
浏览器使用实际知识图谱页面、画布和HTTP客户端，拦截为合成响应；禁用项目环境文件和代理，
阻断未声明API及外部请求。系统临时目录保存结果和截图。
这些验证不代表真实案件的模型识别召回率或身份判断准确率。
