# 时间规律总结

在现有页面、Python 服务和任务输出数据库中增加确定性统计，不改变提取、入报、
两阶段报告生成或事件簇分析的执行流程。查看或生成本页统计不调用模型、不重建图谱，
不回写来源数据库，不新增业务数据库。当前结果是可重新计算的页面统计，不会自动追加到历史报告。

## 使用

- 综合时间线：点击列表／表格旁的“时间规律”，继承当前任务、事件类型和时间范围。
- 即时通讯取证：选择微信或 QQ 导入，进入“时间规律”页签。
  已有原始任务上下文时，读取该任务的微信派生消息表；不将另一个导入混入。
- 选择分析时区、开始／结束日期；事件可按来源筛选，通讯可按会话标识和收发方向筛选。
- 点击“生成时间线总结”。修改筛选条件会清除旧结果，需明确重新生成。
- 点击小时柱、星期小时格、重复时段、通讯方向或日期行，查看对应来源记录。
  有效／缺失／无效／推定／处理时间数量也提供回查。

## 统计口径

1. 24小时分布：计数为当前有效记录数，不是操作次数或在线时长。
2. 重复时段：至少3个独立日期出现记录才列为重复时段，最多列前5项；
   按独立日期数、记录数降序，小时升序排列。分母是有记录日期数，不表示完整覆盖天数。
3. 星期小时分布：星期一为0，小时0—23，按明确的 IANA 时区计算。
   夏令时回拨时，同一当地小时的两次出现合计，来源回查保留各自 UTC 偏移。
4. 日期变化：只列有有效记录的日期；仅当前一自然日也有记录时显示差值。
   不填补缺失日期为“无活动”，不根据零记录推断人员不在线。
5. 通讯：发出、收到、系统、未知方向分别计数及按小时统计。
   微信按 `isSend/is_send`，QQ按既有 `40013` 字段（1/2发出、0收到，其余未知）。
   微信系统／撤回类型10000/10002、QQ已知灰条类型10单列。
   收到消息不证明账号主人当时操作；记录归属也不证明具体操作者。

事件秒时间、微信毫秒时间、QQ秒时间由来源契约决定，不猜测换算。
空值／空串／0计为时间缺失；非数值、负数、非有限值或无法转换的值计为无效。
无法按UTF-8解码的文本（历史编码文件名等）按替换字符读取并正常计数，不中断统计。
文件系统 `DELETED` 的推定时间、工件 `*_ARTIFACT` 的处理时间不进入有效分布。
文件 MACB 时间戳可统计，但单独标记为文件元数据，不解释为完整操作日志。
后台日志仍属于记录，页面可按事件来源筛选，模型或页面不会自动将其归为人为行为。

Unix秒区间沿用现有综合时间线的闭区间，日历日期按所选时区包含首尾日；
两者同时存在时取交集。缺失／无效时间无法归入日期区间，其数量来自同一
非时间筛选范围，并在页面明确说明。小时、日期和收发图的分母仅为有效记录。

## 去重、截断与版本

按同一来源表的原始记录标识和读取字段内容去重：
事件 `id`；微信优先 `msgSvrId`，无可用服务端标识时用 `msgId`；
派生微信行 `id`；QQ表内消息标识。相同标识但字段内容不同的记录保留并计入冲突数。
不同来源不自动合并；同时间、同内容但不同标识的记录也不凭猜测删除。

每轮最多扫描100000条候选记录，顺序为来源表顺序、表内 SQLite rowid 升序。
事件类型／来源、会话筛选在扫描前应用；时间及收发筛选在扫描中应用。
即使达到预算，也统计各表候选数量，返回未扫描数量。
大库中时间筛选可能只命中未扫描部分，此时结果明确为部分统计，不能代表全量。
数据库查询有30秒执行预算，超时返回不可用，不伪造空统计。
日期明细最多3660个有记录日期；小时及星期聚合仍包含全部已扫描有效记录。
来源列表每页50条（接口最多100条）；正文最多展示8000字符，截断单独标记。

每项结果通过 `context_id` 关联同一响应中的完整 `context`：

- 来源类型、任务／导入标识、记录来源层级、原始时间单位；
- 时间、日期、时区、事件类型／来源、会话及收发筛选；
- 有效、缺失、无效、推定、处理、重复、冲突及范围外记录数量；
- 候选数、扫描数、未扫描数、缺失表、截断状态和有记录日期数；
- 去重规则 `same-source-original-id-and-payload:v1`；
- 统计版本 `timeline-summary:v1`；
- 数据库及 WAL／journal 的状态版本和已扫描字段投影哈希。

状态版本是乐观并发指纹，不是原始证据的文件内容哈希。
扫描使用只读 SQLite 事务；开始及结束核对版本。
回查必须携带 `source_version`、`summary_id` 和同一组筛选条件：
来源、筛选或统计契约变化返回409，不展示与旧统计不一致的新记录。
回查保留来源表／行号、来源记录标识、原时间值、时区转换值和读取字段哈希，
不按文件名回退匹配，不声称派生表行号就是原设备数据库主键。

## 接口

均为现有服务中的 GET 读接口，沿用现有认证与读取权限：

| 范围 | 总结 | 回查 |
| --- | --- | --- |
| 任务 | `/api/associations/timeline-summary` | 同路径加 `/records` |
| 微信导入 | `/api/wechat/forensics/imports/{import_id}/timeline-summary` | 同路径加 `/records` |
| QQ导入 | `/api/qq/forensics/imports/{import_id}/timeline-summary` | 同路径加 `/records` |

任务参数：`task_id`、`source=events|wechat`。既有 `wx_<id>`／`qq_<id>` 图谱来源标识
可在 `source=wechat` 下解析到相应导入，不会重建 `graph.db`。
通用筛选：`timezone`、`start_time`／`end_time`（秒）、
`start_date`／`end_date`（日期）、`event_type`、`event_source`、`talker`、
`direction=all|sent|received|unknown|system`。不适用的筛选返回422。
回查额外参数：`source_version`、`summary_id`，以及 `hour`、`weekday`、`day`、
`record_direction`、`quality`、`record_ref`、`offset`、`limit`。
未知／重复参数被拒绝；客户端不能指定数据库路径。

## 回归

Python（Linux环境）：`python -m pytest tests/unit/test_timeline_summary.py -q`。
前端在 `web`：`npm test -- --run src/components/timeline/TimelineSummaryPanel.test.jsx src/pages/IMForensics/IMForensics.test.jsx`。
无头浏览器在 `web`：`node ../scripts/timeline_summary_browser.mjs`。
Windows默认使用Edge，其他环境通过 `CHROME_BIN` 指定浏览器。

浏览器脚本挂载实际时间线及通讯页面和 HTTP 客户端，使用合成响应，禁用项目环境文件和服务代理，
阻断外部请求及未声明的 API 请求。结果和截图写入控制台给出的系统临时目录。
这些验证覆盖统计与交互契约，不代表真实案件材料的覆盖完整度或人员行为判断准确率。
